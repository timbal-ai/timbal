## Events and transcripts

`VoiceSession.run()` yields typed events from `timbal.voice`. The server converts them to transport JSON; WebRTC and LiveKit carry speech on audio tracks instead of JSON audio frames.

```python
from timbal.voice import (
    AudioOutput,
    SessionInterrupted,
    TurnMetricsEvent,
    VoiceUsageEvent,
)


async def play(session, playback, microphone_chunks):
    """session is a VoiceSession; microphone_chunks yields PCM16 mono bytes."""
    async for event in session.run(microphone_chunks):
        if isinstance(event, AudioOutput):
            await playback.write(event.data)
        elif isinstance(event, SessionInterrupted):
            await playback.clear()
        elif isinstance(event, TurnMetricsEvent):
            print(event.metrics.model_dump())
        elif isinstance(event, VoiceUsageEvent):
            print(event.model_dump())
```

`session.transcript` contains committed user and assistant entries with timestamps. Fillers are marked `filler=True`. At session end, the server sends `session_transcript` followed by `session_ended`. Transcript text reflects interruption handling and may contain only the heard prefix of a cancelled assistant reply. If the caller then produces an empty commit or only a pure acknowledgement, the session speaks the unheard remainder without another model call and appends that remainder as its own assistant entry. A genuine next request does not add that entry. The heard prefix stays the interrupted assistant entry.

The stored trace follows the same rule. For an interrupted turn, the agent run's output and the assistant message in its memory hold the heard prefix, marked `metadata["interrupted"] = True`; the output is empty and the memory message dropped when nothing was heard. The model call's span keeps the full generated reply, so you can compare what was said with what was heard.

## Latency

`TurnMetricsEvent` reports millisecond durations and a `run_id` for joining a voice turn to the agent trace. Unobserved stages have `None`, not zero.

- `speech_end_to_transcript_ms`: speech-end evidence to the committed transcript. `speech_end_source` identifies VAD or the coarser partial-transcript estimate.
- `eou_to_llm_first_token_ms`: committed transcript to the first model text delta.
- `eou_to_first_audio_ms`: committed transcript to the first emitted speech bytes. This excludes transcription delay and network/client playback delay.
- `turn_total_ms`, `llm_total_ms`, and `tts_total_ms`: turn and stage durations.
- `interrupted`, `heard_bytes`, and `playback_acks_received`: interruption and playback evidence.
- `filler_spoken` and `filler_count`: whether a latency-masking phrase was spoken. When present, first-audio latency can measure the filler rather than the substantive answer.
- `event`: true when the turn was started by a session event or an announced background result, not by the caller.
- `vad_endpointed`: whether Silero endpointing forced the commit.
- `predictive_endpoint`: whether that commit used a during-speech end-of-turn prediction. It is true only when `vad_endpointed` is also true.
- `speculative`: true when this turn started before the transcript was confirmed. `eou_to_first_audio_ms` is still measured from that confirmation, so 0 means audio was already waiting.
- `speculative_generations_started` and `speculative_generations_discarded`: running totals for the call. A discarded attempt is one the caller resumed, or whose confirmed transcript did not match, or that was interrupted, or the STT stream ended. The same totals are usage keys `speculative_generations:started` and `speculative_generations:discarded` on the turn's run.

## Silence to first audio

The caller-facing wait is `speech_end_to_transcript_ms + eou_to_first_audio_ms`: the caller goes quiet, the transcript is committed, and the first speech bytes are emitted. Read the p50 and p95 of that per-turn sum. Adding a p95 of transcription to a p95 of first audio describes a turn where both stages were slow at once, which is a larger number than the tail callers actually hit.

`speech_end_source="vad"` is the last speech frame, back-dated past the silence the detector had to hear. `"partial"` uses the last interim transcript and reads low, because some transcriber delay is already inside the anchor. `report.by_speech_end_source` splits that same per-turn sum by anchor, so compare calls on the `vad` row. Turns with either clock missing are left out, not counted as zero. A session event or greeting (`event`) has no caller silence and is left out too. Filler turns are counted: the clock stops at the filler, and `filler_spoken` marks those turns. The sum stops at the first byte the server sends and excludes client playback delay.

```python
from timbal.voice.latency import gate_silence_to_first_audio, summarize_turn_metrics
from timbal.voice.metrics import TurnMetrics


def turn(index, speech_ms, audio_ms, **extra):
    fields = {
        "turn_index": index,
        "user_text_chars": 24,
        "speech_end_to_transcript_ms": speech_ms,
        "speech_end_source": "vad",
        "eou_to_first_audio_ms": audio_ms,
        "turn_total_ms": speech_ms + audio_ms,
        "interrupted": False,
        "tts_segments": 1,
        "audio_bytes": 3200,
    }
    fields.update(extra)
    return TurnMetrics(**fields)


report = summarize_turn_metrics(
    [
        turn(1, 80.0, 420.0),
        turn(2, 120.0, 680.0),
        turn(3, 40.0, 160.0, speech_end_source="partial"),
        turn(4, 1.0, 1.0, event=True),
    ]
)
assert report.samples == 3
assert report.p50_ms == 500.0
assert report.p95_ms == 770.0
assert report.by_speech_end_source["vad"].p50_ms == 650.0
assert report.by_speech_end_source["vad"].p95_ms == 785.0
assert report.by_speech_end_source["partial"].p50_ms == 200.0
assert report.excluded_counts == {"event_turn": 1}
assert gate_silence_to_first_audio(report, p95_ms=1000) == []
```

After a call, `session.metrics` holds these `TurnMetrics`, so you can pass it straight to `summarize_turn_metrics`. Stored traces carry each turn on the root span as `voice_turn_metrics`. Run the report on a JSONL trace (or a directory of them):

```bash
python -m timbal.voice.latency traces.jsonl
python -m timbal.voice.latency traces.jsonl --json
python -m timbal.voice.latency traces.jsonl --p95-ms 1000
```

`--json` prints the same report as JSON. With `--p95-ms`, the command exits with status 1 when the p95 is above the ceiling, and when the file has no measured caller turns. It exits with status 2 when a path does not exist. Without `--p95-ms` it only prints the report.

Measure time to the useful answer as well as first audio. Compare providers on representative calls, including slow tools, short acknowledgements, background noise, and interruptions.

## Prompt cache on the text model

Join `TurnMetricsEvent.run_id` to the text agent's run and read `OutputEvent.usage`. OpenAI and Groq report cache reads as `input_cached_tokens`. Anthropic, including Claude on AWS Bedrock, reports them as `cache_read_input_tokens`. A zero count on the first turn is normal. Later turns in the same call read the prefix when it is long enough and the instructions, tools, and per-call lines are unchanged.

## Provider-reported speech usage

OpenAI transcription and mini-TTS adapters emit `VoiceUsageEvent` independently of transcripts and audio. These events carry provider quantities, not dollar amounts. Other providers and custom adapters emit nothing unless they implement the usage capability.

`VoiceSession.prepare()` (which `run()` calls) already forwards adapter usage onto the session event stream, and the server sends those as `{"type": "voice_usage", ...}`. Register another listener only when you need a queue that outlives the client connection. Registering the session's own listener a second time delivers each event twice:

```python
import asyncio

from timbal.voice import VoiceUsageEvent


def listen(session) -> asyncio.Queue[VoiceUsageEvent]:
    usage_queue: asyncio.Queue[VoiceUsageEvent] = asyncio.Queue()
    listener = usage_queue.put_nowait
    session.stt.add_usage_listener(listener)
    session.tts.add_usage_listener(listener)
    # A separate consumer drains and persists the queue, including after disconnect.
    # Remove listeners when these adapters are no longer used.
    return usage_queue
```

Listeners are synchronous and must not block. Listener failures are logged and isolated from speech. Delivery is in-process; your consumer must persist records durably.

`provider`, `operation` (`stt` or `tts`), and `model` identify the resolved operation. Deduplicate by `usage_id`; prefer a complete report over an earlier incomplete report with the same ID. `request_id` and `item_id`, when present, help reconcile provider operations.

`status="complete"` means terminal provider counters arrived. `status="incomplete"` means quantities are missing, invalid, or unavailable after cancellation, error, or closure. Incomplete is not zero cost. `usage` preserves the provider object, including any partial details.

OpenAI transcription can report token usage with separate input audio/text details, or duration usage with `seconds`. Mini-TTS reports input text and output audio tokens through the Speech API's SSE completion event. Legacy `tts-1` and `tts-1-hd` use PCM streaming and do not supply these SSE usage reports. Do not apply one text rate to `total_tokens` or charge both an estimate and the reported quantities. Generated or cancelled audio can be billed even when the caller never hears it.

Apply the resolved speech model's published rates separately from the text agent's `OutputEvent.usage`. The text model catalog and cost SQL generator do not provide a complete speech rate card. Use an explicit estimate policy for incomplete operations, and label those estimates.

## Recordings and client audio

See [Recording calls](/voice/recording) to save session audio locally or separate the speakers. [Thinking sounds](/voice/thinking-sounds) and [background audio](/voice/background-audio) are played by the browser and do not appear in the server's audio recording.
