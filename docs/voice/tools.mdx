A voice agent uses regular Timbal tools. The caller asks a question, the text agent decides to call a function, and its answer is spoken back. Speech adapters do not execute the tool themselves. Keep the system prompt to spoken behavior, and put a rule that matters only for one tool in that tool's description. See [Voice prompts](/voice/prompts).

## Add one lookup

After the [quickstart](/voice/quickstart) and [greetings](/voice/greetings), replace `agent.py` with this complete example. Keep the same `.env` and server command:

```python agent.py
import asyncio

from timbal import Agent


async def get_delivery_status(order_id: str) -> dict:
    """Look up the delivery status of an order by its ID."""
    # Demo delay so you can hear what waiting for a tool feels like.
    # Remove it when replacing this mock with your real service.
    await asyncio.sleep(4)
    orders = {
        "101": {"status": "shipped", "expected_delivery": "tomorrow"},
        "102": {"status": "processing", "expected_delivery": "not yet scheduled"},
    }
    return orders.get(order_id, {"status": "not found"})


agent = Agent(
    name="voice_assistant",
    model="openai/gpt-5-mini",
    system_prompt=(
        "You help callers check deliveries. Ask for the order ID if it is missing. "
        "Use get_delivery_status before giving a delivery status; never invent it. "
        "Reply in one or two short spoken sentences."
    ),
    tools=[get_delivery_status],
    voice_config={
        "language": "en",
        "greeting": "Hi, I can help check your delivery. What's your order ID?",
    },
)
```

Restart the server and start a new session. Say "Check order 101." You should see `Calling get_delivery_status…`, wait through the demo lookup, then hear that the order is shipped and expected tomorrow. An unknown ID should produce a not-found answer. These are mock records, not a live delivery integration.

## What the caller hears while waiting

With the thinking sound off and no filler configured, a tool call can leave a quiet gap. This is a good baseline: first verify that the tool is called and its result is used. The next lessons add a [thinking sound](/voice/thinking-sounds) or a [spoken filler](/voice/fillers) to that gap.

## Speak before a tool call

You can ask the model to say a short acknowledgement before calling a tool, such as
"Let me check that…". Timbal flushes that text to speech while the tool runs,
including phrases ending in an ellipsis. The tool does not wait for synthesis to
finish. The final answer follows the acknowledgement in the same turn.

For a short pause between the acknowledgement and the result, set:

```python
agent.voice_config["tool_beat_secs"] = 0.6
```

The default is `None` (disabled); `0` also disables the pause. A positive value
sets the minimum silence after pre-tool playback and before post-tool synthesis.
Tool execution continues during playback and the pause, so a sufficiently slow
tool adds no extra wait. There is no pause before the first spoken response when
the model called the tool without an acknowledgement.

An enabled pause finishes the pre-tool streaming TTS context and uses a new
context for the result. With the pause disabled, providers that support flushing and confirming delivery of each audio segment
keep their context open across the tool call. Other providers finish the context
at the boundary so interruption tracking never counts unspoken result text as heard.

## Keep a tool from being cut off

By default the caller can barge in at any time, including while a tool runs. That cancels the tool and cuts the reply down to the words already heard. A payment confirmation or a disclaimer should finish. Set `interruption_mode` on the tool:

```python
from timbal import Agent, Tool


async def confirm_payment(order_id: str) -> str:
    """Confirm a payment and read the result back in full."""
    return f"Payment for {order_id} is confirmed."


agent = Agent(
    name="voice_assistant",
    model="openai/gpt-5-mini",
    system_prompt="You confirm payments. Reply in one or two short spoken sentences.",
    tools=[
        Tool(
            handler=confirm_payment,
            interruption_mode="disable_during_tool_and_turn",
        )
    ],
)
```

- `allow` (the default): the caller can interrupt at any time.
- `disable_during_tool`: barge-in is ignored only while the tool runs. The spoken reply after it can still be interrupted, and that interruption still keeps only the words the caller heard.
- `disable_during_tool_and_turn`: barge-in is ignored while the tool runs and until the reply that follows has been played. If the tool pauses for approval or `ask_user`, the caller can speak while the call is waiting, and the reply after they answer is still played through.

This only holds back the caller's barge-in. `session.close()` and an event sent with `announce="interrupt"` still cut the turn.

Speech during the protected window is still transcribed. Those words open the next turn, after the protected audio has finished. When several tools run in the same step, the strictest mode among them covers the whole batch. A plain function passed in `tools` stays `allow`. The same field on an `MCPServer` is copied onto every tool that server exposes.

An agent or workflow in `tools` takes `interruption_mode` too, and it covers that whole call. A mode on a tool inside the nested agent applies only when that agent is the one talking to the caller.

## Add real actions carefully

Replace the mock with an async service call when the basic flow works. For actions requiring approval, wrap the function in `Tool(handler=..., requires_approval=True)` and implement the approval UI and HTTP resume flow. The playground displays a pending request; it does not resolve approval from spoken words. See [Approval gates](/human-in-the-loop/approval-gates) and [Voice approval events](/voice/transports#approval-and-input-requests).

A filler is an acknowledgement of waiting, not confirmation that an action succeeded. Give the final spoken confirmation only after the tool result supports it.

## Report back when slow work finishes

Work that takes minutes should not hold the turn. Start it, let the call continue, and have the agent speak up when it lands.

When the slow work is one of the agent's own tools, run it in the background and turn on `announce_background_results`. The tool returns at once, and when it finishes the agent takes a turn of its own to tell the caller:

```python agent.py
import asyncio

from timbal import Agent, Tool


async def build_report(topic: str) -> str:
    """Build a sales report on a topic. It takes a while; the caller hears back when it is ready."""
    await asyncio.sleep(20)  # stands in for the slow job
    return f"Sales for {topic} are up 4% this quarter."


agent = Agent(
    name="voice_assistant",
    model="openai/gpt-5-mini",
    system_prompt="You help callers with sales reports. Reply in one or two short spoken sentences.",
    tools=[Tool(handler=build_report, background_mode="always")],
    voice_config={"language": "en", "events": {"announce_background_results": True}},
)
```

When the work happens elsewhere (another service, a job queue, a browser tab), report it with `session.notify(text)`. `current_voice_session()` returns the live session to a tool and to any task it starts:

```python
from timbal.voice import current_voice_session


async def on_job_finished(session, job) -> None:
    event = await session.notify(
        f"The {job.topic} report is ready: {job.summary}. Tell the caller briefly.",
        key=f"report:{job.id}",
    )
    print(event.state)  # "pending" until a turn takes it
```

Either way, the result reaches the model as a runtime message, never as something the caller said: it is not in the transcript or the captions, and it stays in memory for later turns. The agent waits for a quiet line (the caller not talking, its own audio finished, no greeting pending). If the caller speaks first, the result comes with their turn instead, ahead of what they said. Results waiting together are spoken in one turn, and a `notify` with the same `key` replaces one that has not been delivered yet. The model may decide there is nothing worth saying; then the agent stays quiet, and no filler plays. While the agent is waiting on the caller (an approval, `ask_user`), it does not speak up.

`notify()` returns a receipt at once: `await event.settled()` reports `"delivered"` once a turn has it (`event.run_id`) or `"superseded"` when a newer event with the same key replaced it. Without `announce_background_results`, a finished background task still reaches the agent, on the caller's next turn. A client can send events over the call's data channel when the server allows it; see [Voice transports](/voice/transports#reporting-events).

### Choosing what speaks up

Each tool and each event can override the call's default with an announce policy:

```python
from timbal import Tool


async def book_table() -> str:
    """Book a table for the caller."""
    return "Booked."


async def sync_crm() -> str:
    """Sync the caller into the CRM."""
    return "Synced."


book = Tool(handler=book_table, background_mode="always", background_announce="when_idle")
sync = Tool(handler=sync_crm, background_mode="always", background_announce="silent")


async def announce_alarm(session) -> None:
    await session.notify("The fire alarm test starts in one minute.", announce="interrupt")
```

- `"when_idle"`: take a turn once the line is quiet (the default for `notify`).
- `"silent"`: never take a turn; the result reaches the caller's next turn. This is the default for background tools unless `announce_background_results` is on.
- `"interrupt"`: speak now. The agent cuts its own reply short, as if the caller had barged in, and what the caller already heard stays in memory. It still waits while the agent is parked on the caller (an approval, `ask_user`). Keep it for things that cannot wait. Events from the caller's device cannot interrupt.

### Progress while the work runs

A background tool can narrate its progress with `report_progress`. Each report is spoken like a `notify` once the line is quiet, a newer report replaces one not yet spoken, and the model is told the work is still running:

```python
from timbal.state import report_progress


async def book_flight(origin: str, destination: str) -> str:
    """Book a flight. Takes about a minute."""
    options = await search_flights(origin, destination)
    report_progress(f"Found {len(options)} options; confirming the cheapest.")
    return await confirm(options[0])
```

Pass `announce="silent"` to keep reports for the caller's next turn instead.

### Telling the client

When the agent takes a turn of its own, the client gets an `event_turn_started` event (`task_ids`, `event_ids`, `keys`, `urgent`) before any text or audio, so a UI can show the reply as an announcement rather than an answer. The wire metrics message is `{"type": "metrics", "metrics": {...}}` with `metrics.event` true. The same object is stored on the trace root as `voice_turn_metrics`. `events` (including `announce_background_results` and `on_busy`) is server config; a client hello cannot set it.

A text turn on the same conversation while the call is live (a chat tab continuing from the call's run) is let in only while the call is not mid-turn. While a call turn runs, the chat turn is refused, or queued with `"events": {"on_busy": "enqueue"}` in the server's `voice_config`. Once let in, the chat turn continues from the call's latest turn, even if the chat sent an older run as its parent, so neither side loses what the other said. A caller who speaks while the chat turn runs is answered after it, and the call continues from what the chat said. An `"interrupt"` event goes ahead of a queued chat turn, but waits for one that is already running.

## Wait for a confirmed turn

With speculative generation on, the model can decide on a tool while the caller might still be pausing, but the tool does not start until the turn is confirmed. That includes lookups. The handler waits, and so do its pre-hook, any approval question, and a default parameter that calls another service. If the caller keeps talking, the wait is cancelled and none of them run. `defer_until_eot=True` marks a tool whose work cannot be undone, such as booking, charging, sending, or hanging up. Speculative generation holds every tool the same way, so the flag is not what turns the hold on. An MCP tool annotated destructive still gets the flag, whether or not `approval` also gates it. With speculative generation off, tools run when the model calls them, which is already after a confirmed transcript.

```python
from timbal import Agent, Tool


async def book_table(name: str) -> str:
    """Reserve a table under this name."""
    return f"Booked for {name}."


agent = Agent(
    name="voice_assistant",
    model="openai/gpt-5-mini",
    system_prompt="You book tables. Reply in one short spoken sentence.",
    tools=[Tool(handler=book_table, defer_until_eot=True)],
    voice_config={"language": "en", "speculative_generation": {"enabled": True}},
)
```

`end_call` below hangs up. With speculative generation on it waits for a confirmed turn like every other tool, whether or not you set `defer_until_eot`. See [Turn-taking and interruptions](/voice/turn-taking#speculative-generation).

## Let the caller end the call

Give the model a tool that ends the call, and have it say goodbye in that same reply, before the tool runs. Two calls do different jobs.

`await session.commit_hangup()` is the one to use when `hangup_grace_secs` is set. It waits until any goodbye already playing has finished, then for that many quiet seconds. If this reply has not spoken yet, the session says a short farewell first and waits on that audio. A real follow-up in that span ("wait", "one more thing", a new request) returns false and does not hang up. A short acknowledgement ("alright", "okay") or another goodbye does not, including a repetition ("Alright. Alright."). An unfinished partial that can still become one of those does not either ("Al" or "Alri" on the way to "Alright"). `commit_hangup` returns false without starting the window when this turn's caller words are not a goodbye. Thanks, "vamos", and "vámonos" do not hang up. A clear goodbye still does, including one after acknowledgements ("Vale, gracias. Adiós."). A partial that is already a retract ("wait", "no") cancels immediately. True means the window already passed: it then calls `end_call(grace_secs=0)`, so there is no second quiet window after the tool returns. Return a short "Ending the call." Do not ask for a goodbye in that success result. Once the tool and any tool called alongside it have returned, the model is not asked for another step. Any line it still produces after True is not played. Filler and soft-timeout lines do not play on this wait. After a false result, a later clear goodbye still hangs up, including when the model only says goodbye and does not call the tool again.

```python agent.py
from timbal import Agent, Tool
from timbal.voice import current_voice_session


async def end_call() -> str:
    """End the call after the goodbye in this same reply has been heard."""
    session = current_voice_session()
    if session is None:
        return "There is no call to end."
    if not await session.commit_hangup():
        return "Do not hang up. Keep helping."
    return "Ending the call."


agent = Agent(
    name="voice_assistant",
    model="openai/gpt-5-mini",
    system_prompt=(
        "When the caller says a clear goodbye or asks you to hang up, "
        "say a short goodbye and then call end_call. "
        "Thanks or done is not a goodbye."
    ),
    tools=[Tool(handler=end_call)],
    voice_config={"hangup_grace_secs": 1.5},
)
```

`session.end_call()` requests teardown immediately and returns. The session still waits for the goodbye to finish playing, including a goodbye the model speaks on a later step of the same turn. If `hangup_grace_secs` is set, that wait is followed by the quiet window, and speech then cancels the close. The tool has already returned, so the irreversible request is already in flight. Use this when you want the result itself to ask for a goodbye the model has not said yet.

```python agent.py
from timbal.voice import current_voice_session


async def end_call() -> str:
    """End the call when the caller asks to."""
    session = current_voice_session()
    if session is None:
        return "There is no call to end."
    session.end_call()
    return "If you have not said goodbye yet, say it now in one short sentence. The call ends once it has been heard."
```

If the goodbye never finishes playing, the call ends after 20 seconds, without an extra wait. Calling `end_call` again changes nothing. Speech that cancels the close is any new transcript, or a partial that is not an echo of the goodbye, in whatever language the caller is speaking. Audible speech counts too when local VAD endpointing is on. The assistant can call the tool again on a later turn. `session.end_call(grace_secs=1.5)` sets the window for that one call; `grace_secs=0` hangs up as soon as the goodbye has been heard, even when the session configured a window. Allowed values are from 0 to 30 seconds. A client hello may set `hangup_grace_secs` the same way it sets `tool_beat_secs`. Unset is the default. `commit_hangup()` still speaks a farewell when the reply has not, then calls `end_call()`. That is not the same as calling `end_call()` alone.
