A voice agent uses regular Timbal tools. The caller asks a question, the text agent decides to call a function, and its answer is spoken back. Speech adapters do not execute the tool themselves.

## Add one lookup

After the [quickstart](/voice/quickstart) and [greetings](/voice/greetings), replace `agent.py` with this complete example. Keep the same `.env` and server command:

```python agent.py
import asyncio

from timbal import Agent


async def get_delivery_status(order_id: str) -> dict:
    """Look up the delivery status of an order by its ID."""
    # Demo delay so you can hear what waiting for a tool feels like.
    # Remove it when replacing this mock with your real service.
    await asyncio.sleep(4)
    orders = {
        "101": {"status": "shipped", "expected_delivery": "tomorrow"},
        "102": {"status": "processing", "expected_delivery": "not yet scheduled"},
    }
    return orders.get(order_id, {"status": "not found"})


agent = Agent(
    name="voice_assistant",
    model="openai/gpt-4.1-mini",
    system_prompt=(
        "You help callers check deliveries. Ask for the order ID if it is missing. "
        "Use get_delivery_status before giving a delivery status; never invent it. "
        "Reply in one or two short spoken sentences."
    ),
    tools=[get_delivery_status],
    voice_config={
        "language": "en",
        "greeting": "Hi, I can help check your delivery. What's your order ID?",
    },
)
```

Restart the server and start a new session. Say "Check order 101." You should see `Calling get_delivery_status…`, wait through the demo lookup, then hear that the order is shipped and expected tomorrow. An unknown ID should produce a not-found answer. These are mock records, not a live delivery integration.

## What the caller hears while waiting

With the thinking sound off and no filler configured, a tool call can leave a quiet gap. This is a good baseline: first verify that the tool is called and its result is used. The next lessons add a [thinking sound](/voice/thinking-sounds) or a [spoken filler](/voice/fillers) to that gap.

## Add real actions carefully

Replace the mock with an async service call when the basic flow works. For actions requiring approval, wrap the function in `Tool(handler=..., requires_approval=True)` and implement the approval UI and HTTP resume flow. The playground displays a pending request; it does not resolve approval from spoken words. See [Approval gates](/human-in-the-loop/approval-gates) and [Voice approval events](/voice/transports#approval-and-input-requests).

A filler is an acknowledgement of waiting, not confirmation that an action succeeded. Give the final spoken confirmation only after the tool result supports it.

## Report back when slow work finishes

Work that takes minutes should not hold the turn. Start it, let the call continue, and have the agent speak up when it lands: `session.notify(text)` starts a turn from an event instead of from the caller. `current_voice_session()` returns the live session to the tool and to any task it starts:

```python agent.py
import asyncio

from timbal import Agent
from timbal.voice import current_voice_session

_background: set[asyncio.Task] = set()


async def _report_when_done(session, topic: str) -> None:
    await asyncio.sleep(20)  # stands in for a job that finishes later
    await session.notify(
        f"The report on {topic} is ready: sales are up 4% this quarter. Tell the caller briefly.",
        key=f"report:{topic}",
    )


async def start_report(topic: str) -> str:
    """Start a sales report on a topic. It takes a while; the caller hears back when it is ready."""
    session = current_voice_session()
    if session is None:
        return "Reports can only be started during a call."
    task = asyncio.create_task(_report_when_done(session, topic))
    _background.add(task)
    task.add_done_callback(_background.discard)
    return "Started. Tell the caller you will let them know when it is ready."


agent = Agent(
    name="voice_assistant",
    model="openai/gpt-4.1-mini",
    system_prompt="You help callers with sales reports. Reply in one or two short spoken sentences.",
    tools=[start_report],
    voice_config={"language": "en"},
)
```

The note reaches the model as a runtime message, never as something the caller said: it is not in the transcript or the captions, and it stays in memory for later turns. By default the agent waits for a quiet line — the caller not talking, its own audio finished — and never interrupts. If the line stays busy for 30 seconds (`max_wait_secs`), the note is added ahead of the caller's next turn instead. Notes waiting together are spoken in one turn, and a note with the same `key` replaces one that has not been delivered yet. `policy="now"` interrupts whatever is playing. The model may decide there is nothing worth saying; then the agent stays quiet, and no filler plays.

A client can send the same note over the call's data channel; see [Voice transports](/voice/transports#reporting-events).

## Let the caller end the call

`session.end_call()` hangs up once what the agent is saying has been heard. Give it to the model as a tool, and tell it to say goodbye in the same reply:

```python agent.py
from timbal.voice import current_voice_session


async def end_call() -> str:
    """End the call when the caller asks to. Say a short goodbye in this same reply."""
    session = current_voice_session()
    if session is None:
        return "There is no call to end."
    session.end_call()
    return "If you have not said goodbye yet, say it now in one short sentence. The call ends once it has been heard."
```

The session waits for the turn to finish and its audio to play, then closes itself, as `session.close()` does. Some models call the tool before writing the goodbye, so the tool's result asks for one; the goodbye then comes from a second model call in the same turn, and the session still waits for it. If the caller says something first, the call stays up. If the goodbye never finishes playing, the call ends after 20 seconds anyway. Calling it again changes nothing.
