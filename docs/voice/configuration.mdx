Start with [Your first voice agent](/voice/quickstart) for a working conversation. This page is the reference for changing providers and resolving configuration after the basic lessons.

Set `Agent(voice_config=...)` to configure sessions created by the server. Use a sparse dict or `VoiceConfig` so the fields you omit inherit operator defaults. The server applies environment defaults, then the agent's declared settings, then allowed per-call client overrides. The client cannot supply credentials, arbitrary provider hosts, recording paths, or Python detector objects.

## Transcription providers

Set `stt_provider` and optionally `stt_model`. These are adapter IDs and speech model IDs, separate from the `provider/model` IDs used by `Agent.model`.

- **`deepgram`** or **`deepgram-flux`** (default): defaults to `flux-general-multi`; requires `DEEPGRAM_API_KEY`. Flux reports native end-of-turn events, so the session uses `provider` turn detection. When `DEEPGRAM_API_KEY` is unset, each session falls back to `elevenlabs`.
- **`elevenlabs`**: defaults to `scribe_v3_live` (Scribe v3 Live); requires `ELEVENLABS_API_KEY`. Set `stt_model` to `scribe_v2_realtime` to keep the previous model. See [ElevenLabs Scribe](#elevenlabs-scribe).
- **`deepgram-nova`**: defaults to `nova-3`; requires `DEEPGRAM_API_KEY`. Select Nova explicitly or supply a `nova-*` model.
- **`munsit`**: defaults to `munsit-en-ar`; requires `MUNSIT_API_KEY`. Reports native utterance boundaries.
- **`openai`**: defaults to `gpt-transcribe`; requires `OPENAI_API_KEY`. Uses a transcription-only Realtime session with server VAD. It does not report native end-of-turn, so the session uses local turn detection when `timbal[voice]` is installed and lexical detection otherwise. Flux and Munsit are the adapters that force `provider` mode.

Set `language` to the conversation language. It hints transcription and, when set, tells the model to reply in that language. Omit it to follow the user's latest substantive message. See [Reply language](#reply-language). `keyterms` and `stt_languages` are transcription only. They do not change `reply_language`.

```python
agent = Agent(
    name="norte_market",
    model="openai/gpt-5.4-mini",
    voice_config={
        "language": "es",
        "reply_language": "follow",
        "stt_languages": ["es", "en"],
        "keyterms": ["Norte Market", "NM1001"],
    },
)
```

`keyterms` is a list of at most 100 plain phrases (a name, a brand, an acronym). Do not append a Nova weight such as `term:0.15`. Deepgram Flux and Nova-3, and ElevenLabs Scribe, send them when the socket connects. Flux can replace the whole list on that socket with `VoiceSession.set_keyterms`; an empty list clears it. The new list does not merge with the old one, and audio already transcribed is not rewritten. Nova and Scribe cannot replace terms after connect. Scribe takes at most 50 terms of 20 characters each on a call: an agent that sets `stt_provider="elevenlabs"` with more, or longer, fails to load, and a Flux agent that falls back to Scribe sends the terms that fit and logs `el_stt_keyterms_trimmed`. OpenAI and Munsit reject `keyterms` at configuration time. A caller hello cannot set them. Each call copies the agent's list, so one session cannot change another's, and there is no voice handoff that would carry terms across agents.

`language` and `stt_languages` on `flux-general-multi` accept only English, Spanish, French, German, Hindi, Russian, Portuguese, Japanese, Italian, and Dutch (`en`, `es`, `fr`, `de`, `hi`, `ru`, `pt`, `ja`, `it`, `nl`), including regional subtags such as `es-ES`. Catalan, Arabic, Chinese, and any other tag are rejected when the agent config is built. That is a startup check: a Flux agent that used to set `language` to `ca`, `ar`, or `zh` now fails to load instead of opening a socket Flux would reject. `stt_languages` replaces the single `language` hint for speech-to-text and is only for `flux-general-multi`. `flux-general-en` rejects a hint list. `set_language` still replaces the live hint list with one supported tag. These settings do not promise that a word will be recognized, and they do not make Flux recognize Catalan.

`reply_language` is separate. This replies in Catalan and still transcribes with a Spanish Flux hint. Flux does not recognize Catalan. Use another speech provider that accepts `ca` when the transcript itself must be Catalan.

```python
voice_config={"language": "es", "reply_language": "ca", "stt_provider": "deepgram"}
```

Provider-specific transcription options belong in `stt_extra`. Each adapter supports its own options; switching providers does not make an option portable. A non-empty `keyterms` list cannot also set `keyterm`, `keyterms`, `keywords`, or `hotwords` in `stt_extra`. The agent fails to build if any of those keys is present, including when the value is `None`, `""`, or `[]`. Omit the key. An empty `keyterms` (left unset, `None`, or `[]`) does not conflict, and a `keyterm` that exists only in `stt_extra` is still passed through.

### ElevenLabs Scribe

`scribe_v3_live` is the default ElevenLabs model. `scribe_v2_realtime` is still served and takes the same settings, except the two marked below. Scribe options go in `stt_extra` and are sent as given:

```python
agent = Agent(
    name="support",
    model="openai/gpt-5.4-mini",
    voice_config={
        "stt_provider": "elevenlabs",
        "language": "ca",
        "stt_extra": {"diarize": True},
    },
)
```

- **`commit_strategy`**: `"vad"` (the default: Scribe commits after `vad_silence_threshold_secs` of silence), `"manual"`, or `"turn_prediction"` (Scribe v3 Live only). See [Scribe turn prediction](#scribe-turn-prediction) before choosing the last one.
- **`vad_silence_threshold_secs`**: 1.2 by default here. Scribe accepts 0.192 to 3.0.
- **`turn_commit_threshold`**: 0.75 on Scribe v3 Live. Commits when Scribe's turn probability reaches that score, without waiting out the silence. `0` or `None` turns it off. See [Scribe turn prediction](#scribe-turn-prediction).
- **`diarize`**: Scribe v3 Live only. Each committed transcript is followed by a `TranscriptEvent` of type `diarized`, whose `speakers` list holds one `SpeakerSegment` (`speaker_id`, `text`, `start`, `end`) per run of words from the same speaker. `VoiceSession` ignores these events: they never start a turn and are not sent to the client. Read them from `stt.events()` in a [custom pipeline](/voice/custom-pipelines).
- **`secondary_languages`**: other languages the caller may use, next to `language`.

A setting the chosen model does not accept (`turn_prediction` or `diarize` on `scribe_v2_realtime`, an unknown model id) ends the session with the reason ElevenLabs gave, for example `STT fatal (invalid_request): The 'diarize' parameter is only supported by scribe_v3_live.`

Scribe closes the session when a commit arrives with less than 0.3 seconds of audio since the previous one (`commit_throttled`). The session's endpointer and Scribe can reach the same boundary together, so the adapter does not send a commit within 0.4 seconds of the last one, its own or Scribe's, and logs `el_stt_commit_skipped`. A commit that crosses Scribe's on the wire can still be throttled. That ends the call with `STT fatal (commit_throttled)`.

#### Scribe turn prediction

Scribe v3 Live scores each interim transcript with the probability that the caller has finished. It arrives as `confidence` on `partial` transcript events, under every commit strategy.

`commit_strategy="turn_prediction"` has Scribe commit when that score reaches about 0.9. The score is not adjustable. `vad_silence_threshold_secs` still applies as a ceiling: Scribe commits at that much silence whatever the score. At the default 1.2 seconds it behaves like `"vad"`, except that a finished question or sentence commits about half a second sooner. Raising the ceiling keeps a mid-sentence pause in one piece, and makes short answers slow: the score climbs slowly after "No." or "Okay.", which then take two to three seconds to commit. With the session's local turn detector, a ceiling of 2 or 3 seconds also let the session's commit and Scribe's collide. Keep the ceiling at 1.2 seconds when you use it.

`turn_commit_threshold` applies a score of ours instead, and it is what a session uses by default. The adapter commits when a partial reaches it, and Scribe's silence ceiling stays as the backstop. The default is 0.75 on Scribe v3 Live with `commit_strategy="vad"`. `scribe_v2_realtime` sends no score, so nothing changes there. With `"manual"` it is off unless you set it, and with `"turn_prediction"` it is off: the two commits would collide, and an agent that sets both fails to load.

```python
voice_config={
    "stt_provider": "elevenlabs",
    "stt_extra": {"turn_commit_threshold": 0},  # off: commit on Scribe's VAD silence only
}
```

In the replay harness, with the local turn detector, the default took median dead air from 1.36 to 1.02 seconds and passed every run, where the same sessions without it lost 7 of 156. That is two batches of synthetic audio, not a measurement on your calls.

`turn_commit_partials` (default 1) asks for that many consecutive partials at or above the score with the same words. At 0.75 a caller is rarely cut off mid-sentence. At 0.6 it happens often enough to hear. An utterance Scribe scores low, such as a bare number, waits for the silence ceiling, so a higher ceiling makes those turns slower. Measurements are in `benchmarks/voice/README.md`.

## Speech providers

Set `tts_provider`, `tts_model`, and `voice` for the output provider:

- **`elevenlabs`** (default): defaults to `eleven_v4_turbo`; requires `ELEVENLABS_API_KEY` and an accessible ElevenLabs voice ID. Supports incremental text through one streaming context per reply. Set `tts_model` to `eleven_flash_v2_5` for the previous default.
- **`deepgram`**: defaults to `aura-2-thalia-en`; requires `DEEPGRAM_API_KEY`. The full Aura model ID identifies the voice and language.
- **`fishaudio`**: defaults to `s2.1-pro`; requires `FISH_API_KEY`. Use a Fish reference voice ID for `voice` when selecting a reference voice.
- **`munsit`**: defaults to `faseeh-v1-preview`; requires `MUNSIT_API_KEY`. The fallback voice is `MUNSIT_VOICE_ID` or `ar-uae-male-1`.
- **`openai`**: defaults to `gpt-4o-mini-tts` and `coral`; requires `OPENAI_API_KEY`. Synthesizes complete text segments as they become ready.

By default every segment, including the first, waits for a sentence. Set `first_flush_min_words` to any whole number from 1 to 40 (`4` is the useful value) to let the first segment start at a comma once it has that many words, so a long opening sentence is not held until its period. "The return window is thirty days, so you can still send it back." then starts speaking at the comma. "Hello, how are you?" does not: that comma is one word, and the segment waits for the sentence. Later segments still wait for a sentence boundary: a period, exclamation mark, question mark, semicolon, colon, or newline, including the Arabic question mark and semicolon and the fullwidth question mark and exclamation mark. Punctuation inside titles (`Dr.`, `Sr.`, `Sra.`), initials (`U.S.`), times (`3:00`, `a.m.`), numbers (`3.14`, `1,234`), and ellipses (`...`) is not a boundary. `first_flush_min_words` is an agent setting. A caller hello cannot set it.

```python
from timbal import Agent

agent = Agent(
    name="voice_assistant",
    model="openai/gpt-5-mini",
    system_prompt="Reply in one or two short spoken sentences.",
    voice_config={"language": "en", "first_flush_min_words": 4},
)
```

Use the chosen provider's voice ID. `language` sets the reply language and the transcription hint. It does not select a Deepgram Aura voice. Output style options belong in `tts_extra`. See [Speech examples](/examples/agents/tts) for detailed OpenAI and Deepgram settings.

The default session audio is mono PCM16 little-endian at 16,000 Hz (`sample_rate=16000`, `encoding="pcm_s16le"`). Transports convert their wire formats where needed. OpenAI uses 24 kHz on the provider connection and requires the voice extra to resample other session rates.

`stt_extra` defaults to ElevenLabs-oriented VAD keys (`commit_strategy`, `min_speech_duration_ms`, `vad_silence_threshold_secs`, `vad_threshold`). The server strips those keys for adapters that own end-of-turn. For Deepgram Flux, `eot_threshold`, `eot_timeout_ms`, and `eager_eot_threshold` in `stt_extra` are the connect-time end-of-turn knobs. `tts_extra` defaults to `{"auto_mode": true}`. `VoiceConfig.model` is a per-session text-model override (`provider/model`), separate from `stt_model` and `tts_model`.

`entity_patience` (default false) and `entity_patience_secs` (default 2.5, maximum 10) hold a turn that still ends in a number, spoken number words, letter names, spelled letters, an email, or an alphanumeric code. See [Turn-taking and interruptions](/voice/turn-taking#entity-and-spelling-patience).

## Pace synthesized speech

Both controls are off unless you set them, and both need the `timbal[voice]` extra. They apply only to the cascaded pipeline (transcription, then the agent, then speech), not to a `RealtimeSession`. They run on the PCM the caller hears, after the speech provider returns it, and only when the session encoding is PCM16 (`pcm_s16le`, or the `linear16` / `pcm16` aliases). Any other encoding is left unchanged and a warning is logged. An interrupted reply is still cut to the audio that was actually played.

`max_tts_pause_secs` must be `0` or greater. It shortens an internal silence quieter than `tts_quiet_dbfs` (default `-45`, which leaves breaths in) down to that many seconds. Pause trimming does not delay the start of the reply. `tts_tempo` must be greater than `0`. It changes the speaking rate without changing the pitch: `1.0` leaves the audio alone, and a value above `1` is faster. Tempo holds 20–50 ms before the first samples, and a short tail is flushed once no new audio arrives for 0.25 s. `None` on either field disables it. An invalid value in a client hello is dropped and the server's value is kept.

```python
from timbal import Agent

agent = Agent(
    name="voice_assistant",
    model="openai/gpt-5-mini",
    system_prompt="Reply in one or two short spoken sentences.",
    voice_config={"language": "en", "max_tts_pause_secs": 0.2, "tts_tempo": 1.05},
)
```

## What a client may override

A browser or phone hello may set `stt_provider`, `stt_model`, `tts_provider`, `tts_model`, `voice`, `language`, `reply_language`, `sample_rate`, `encoding`, `stt_extra`, `tts_extra`, `vad_endpointing`, `predict_during_speech`, `model`, `tool_beat_secs`, `max_tts_pause_secs`, `tts_quiet_dbfs`, `tts_tempo`, `hangup_grace_secs`, `turn_timeout_secs`, `turn_timeout_fallback`, `filler`, `greeting`, `outbound_greeting`, `user_idle`, `entity_patience`, and `entity_patience_secs`. `max_tts_pause_secs` must be 0 or greater and `tts_tempo` must be greater than 0; an invalid value for either is dropped and the server's value is kept. `hangup_grace_secs` is 0 to 30 seconds. An invalid `reply_language` (a malformed tag or a non-string) is dropped and the server's value is kept. A blank hello value is dropped the same way. `"follow"` and a well-formed tag replace it. A blank, non-string, or non-tag `language` is dropped for every provider, and the agent's language stays. The call still starts. The ten-language check (`en`, `es`, `fr`, `de`, `hi`, `ru`, `pt`, `ja`, `it`, `nl`) applies only when the hello resolves to Flux multilingual: `stt_provider` is `deepgram` or `deepgram-flux`, and the model is not `flux-general-en`, Nova, Scribe, or an OpenAI transcription model. Nova, Scribe, and OpenAI keep a well-formed tag such as `ca`. On Flux multilingual, an unsupported hello `language` is dropped first. If that still cannot keep the agent's own `language` or its `stt_languages`, the hello's `stt_provider` and `stt_model` are both dropped. A Nova agent with `language: "ca"` whose hello selects Flux multilingual stays on Nova with `ca`. A Flux agent with `stt_languages` whose hello selects Nova stays on Flux with that list. A supported tag such as `fr` replaces `language` and does not replace `stt_languages` or `reply_language`. It may also send transport keys `turn_detector` (a mode name), `parent_id` (continue a text run), `direction`, and `call_context`. `call_context` is ignored unless the server sets `TIMBAL_VOICE_ALLOW_CLIENT_CALL_CONTEXT=1`.

Recording, ambient audio, `events`, `speculative_generation`, `hello_wait_secs`, `sip_hello_wait_secs`, `ignore_backchannels`, `hold_unfinished_secs`, `min_delay_secs`, `stop_silence_secs`, `first_flush_min_words`, `keyterms`, and `stt_languages` are server-only. Unknown `VoiceConfig` keys fail at startup (`extra` is forbidden). Empty optional blocks (`greeting`, `filler`, `user_idle`, `ambient`, `recording`, `events`, `speculative_generation`) are treated as unset so they do not wipe an inherited value.

`hesitation` is server-only as well, and an empty `hesitation` block is unset. See [Hesitation sounds](#hesitation-sounds).

## Mix providers

With `OPENAI_API_KEY` configured, this selects OpenAI for transcription and speech while keeping `agent.model` as the conversation model:

```python
from timbal import Agent

agent = Agent(
    name="voice_assistant",
    model="openai/gpt-5-mini",
    system_prompt="Reply in one or two short spoken sentences.",
    voice_config={"language": "en"},
)
agent.voice_config = {
    "stt_provider": "openai",
    "stt_model": "gpt-transcribe",
    "tts_provider": "openai",
    "tts_model": "gpt-4o-mini-tts",
    "voice": "coral",
    "language": "en",
}
```

This assignment replaces the agent's declared config. Keep any greetings or other behavior fields you want to retain. The earlier lessons use a dict and add individual keys to preserve previous behavior; a `VoiceConfig` instance or callable needs its own update pattern.

## Reply language

`voice_config["language"]` is the conversation language, not only a transcription hint.

- **Set** (`"en"`, `"es"`, `"es-ES"`): unless `reply_language` is set, the model is told to reply in that language, including short replies and waiting phrases. A Spanish-first agent keeps `"es"`. The tag is also sent to speech-to-text (`language_hint` on Deepgram Flux multi, `language_code` on ElevenLabs Scribe, `language` on Deepgram Nova). Default OpenAI `gpt-transcribe` sends `languages: [tag]`; other OpenAI transcription models send a single `language`. On `flux-general-multi`, `language` and `stt_languages` accept only `en`, `es`, `fr`, `de`, `hi`, `ru`, `pt`, `ja`, `it`, and `nl`. `ca`, `ar`, and `zh` fail when that Flux config is built. A supported hint plus `reply_language: "ca"` changes the spoken reply only. Flux still does not recognize Catalan. Point `stt_provider` at a provider that accepts Catalan when the transcript must be Catalan.
- **Unset**: unless `reply_language` is set, the model follows the language of the user's latest substantive message (a full request, question, or correction). Accent, fillers, names, and a single word from another language do not switch the reply. If the agent's own system prompt already names one reply language, that instruction stands.
- **`reply_language`**: leave it unset to keep the rules above. `"follow"` makes the reply follow the latest substantive message even when `language` is set as a transcription hint. A well-formed BCP-47 tag pins the reply to that tag and does not change the hint. `set_language` still updates the hint, and it moves the next turn's reply instruction only when `reply_language` is unset.
- **Explicit switch**: the pin yields when the user asks to use another language. Saying a sentence in another language is not, by itself, that request. Call `set_language` when the conversation language should actually change. Unless `reply_language` is set, that moves the next turn's reply instruction and the transcription hint together. With `reply_language` set, only the hint moves.

```python
voice_config = {"language": "es", "reply_language": "follow"}
```

`"follow"` is case-insensitive. On an agent config, a blank string is the same as unset. A malformed tag (`english`, a sentence, `en-`) raises `ValueError` when that config is built. A non-string raises `TypeError`. Accepted `reply_language` tags are two or three letters, an optional four-letter script, and an optional region: `en`, `es-ES`, `zh-Hans`, `es-419`, `ca`. That is the reply pin, not the Flux transcription list. A caller hello that sends a bad or blank `reply_language` does not raise: the value is dropped and the server's `reply_language` stays.

Deepgram Flux applies a supported hint on the open socket. A `Configure` message with `language_hints: ["en"]` replaces a sticky hint; `language_hints: []` clears it and Flux goes back to auto-detect. Audio already transcribed is not reprocessed. Flux processes one `Configure` at a time, so a hint, a keyterm list, or a turn-threshold change is sent after Flux acknowledges the previous message. A newer change of the same kind replaces one that is still waiting. On `flux-general-multi`, `set_language("ca")` raises `ValueError` before the socket or the stored hint changes. The previous hint, including an `stt_languages` list, stays. `reply_language` is not changed. `flux-general-en` does not accept a language hint: `set_language` does not retarget that socket, and the reply pin can still move when `reply_language` is unset. ElevenLabs Scribe, Deepgram Nova, and OpenAI transcription read the hint when the socket opens: `set_language` stores the tag for the next connection and does not retarget the open socket. Unless `reply_language` is set, the reply instruction uses that tag on the next turn. Munsit only sends `language=ar` (`ar` and a tag such as `ar-AE` both become `ar`). Any other tag is dropped (`munsit_stt_language_dropped`) and is not sent on the next connection.

From a tool on the call, `current_voice_session()` is the live session. The tool is not registered for you. Add it only on agents that should be able to switch.

```python
from timbal import Agent
from timbal.voice import current_voice_session


async def set_conversation_language(language: str) -> str:
    """Set the language for the rest of the call.

    Use the BCP-47 tag the caller asked for, such as en or es.
    """
    session = current_voice_session()
    if session is None:
        return "No active call."
    try:
        await session.set_language(language)
    except ValueError as exc:
        return str(exc)
    return f"Conversation language is now {language}."


async def set_transcription_terms(terms: list[str]) -> str:
    """Replace the names and product terms for this call.

    Pass plain phrases, such as ["Norte Market", "NM1001"].
    Pass [] to clear them.
    """
    session = current_voice_session()
    if session is None:
        return "No active call."
    try:
        await session.set_keyterms(terms)
    except ValueError as exc:
        return str(exc)
    return "Transcription terms updated."


agent = Agent(
    name="voice_assistant",
    model="openai/gpt-5-mini",
    system_prompt="Reply in one or two short spoken sentences.",
    tools=[set_conversation_language, set_transcription_terms],
    voice_config={"language": "es"},
)
```

`set_language` returns true when the open transcriber took the hint. On Flux, true means the `Configure` message was sent or queued, not that Flux applied it; a rejection is logged as `dg_flux_configure_failed`. `set_keyterms` reports the same way. Unless `reply_language` is set, the reply instruction uses the new tag on the next turn. A tag that is not BCP-47 raises `ValueError` and leaves the call as it was. On Flux multilingual, a tag outside `en`, `es`, `fr`, `de`, `hi`, `ru`, `pt`, `ja`, `it`, and `nl` raises `ValueError` the same way, before a `Configure` message is sent. `set_keyterms` replaces the whole list. It raises `ValueError` for a weighted phrase such as `term:0.15`, a blank phrase, more than 100 phrases, or a connection that cannot replace terms (Nova, Scribe, OpenAI, Munsit, or Flux with no open socket). The call's previous terms stay. The tools above return that error text instead of failing the turn. The reply line is appended after the agent's own prompt, past the greeting note, so a soft "match the caller" earlier in the prompt does not outrank it.

## Ending the call

`hangup_grace_secs` is the quiet window after a goodbye, from 0 to 30 seconds. Unset hangs up once that audio has played. When it is set, the hangup tool should await `session.commit_hangup()` so the window is spent before teardown. Inside that wait, a short acknowledgement does not cancel it; "wait" and any other request do. Bare `session.end_call()` does not use that split: any new caller speech cancels its close. It still requests teardown immediately and then opens this window. See [Let the caller end the call](/voice/tools#let-the-caller-end-the-call).

## Hesitation sounds

A person on the phone does not open every sentence cleanly. Now and then the first thing out is a sound while the thought forms. `hesitation` puts that sound in front of some replies: "Eh... son diez con sesenta." It is off unless you set it, it is server-side (a caller hello cannot set or clear it), and it applies only to the cascaded pipeline, not to a `RealtimeSession`.

```python
from timbal import Agent

agent = Agent(
    name="voice_assistant",
    model="openai/gpt-5-mini",
    system_prompt="Reply in one or two short spoken sentences.",
    voice_config={"language": "es", "hesitation": True},
)
```

`True` is `{"rate": 0.15}`. `None`, `False`, an empty block and `{"rate": 0}` add nothing.

| Field | Default | What it does |
| --- | --- | --- |
| `rate` | `0.15` | Chance, from 0 to 1, that a reply opening that can take a sound gets one. |
| `openers` | `None` | The sounds. A list serves every language. A dict is keyed by language, as `filler.phrases` is: `"es"`, `"en"`, region dropped, `"*"` for any other. |
| `seed` | `None` | Fixes the draws, for a repeatable test. |

The sound is only in the text sent to the speech provider. Reply deltas, `AgentTextDone`, the transcript and the agent's memory keep the model's words. An opening is the first segment the session speaks at the start of a turn, or the first after a tool call. Nothing else can get a sound: not a later sentence of the same reply, and not a line the session speaks as written (a greeting, a filler, an idle prompt, the hangup farewell, the turn-timeout fallback, the rest of a reply resumed after a false interruption).

An opening gets a sound when all of these hold:

- **It starts with a letter.** Not with a figure, `¿`, `¡`, a quote or a bracket.
- **Its first clause has three words or more.** The first clause ends at the first comma, full stop, colon, semicolon, question mark, exclamation mark, ellipsis or dash that is followed by a space or ends the segment. "Vale,", "De acuerdo.", "Hasta luego," and "Pedro," are an acknowledgement, a goodbye and a name, and are said clean. The comma in "10,60" does not end the clause.
- **The model did not hesitate on its own.** An opening that starts with one of the language's openers ("A ver, ..."), or with a bare "mm", "eh", "ehm", "um", "uh", "hmm", "ah" or "er" of any length followed by a comma, a full stop, an ellipsis or a dash, is left as it is and counts as hesitated.
- **The opening before it was not hesitated**, by the session or by the model. That is the previous turn's opening, or the one before the tool call.
- **A random draw falls under `rate`.**

No two openings in a row are hesitated, so the share that gets a sound is at most `rate`, and it is `rate / (1 + rate)` when every opening can take one: 0.13 for the default, every other one for `1`. The same sound is not used twice running when the language has another. After the sound, the reply's first word loses its capital when its second character is a lowercase letter, so an acronym ("DNI") and a one-letter word ("A", "I") keep theirs.

Write each opener the way the voice should read it, ending in a comma or an ellipsis: `"eh..."` pauses longer than `"eh,"`. It starts with a letter and has at most 24 characters, and a language takes at most 24 of them. A block that breaks one of these rules fails when the config is built. The built-in sounds, used for a language `openers` does not cover (no entry for it and no `"*"`):

| Language | Sounds |
| --- | --- |
| `es` | `eh...`, `mm...`, `pues...`, `a ver,`, `mm,`, `eh,` |
| `en` | `um,`, `well,`, `so,`, `mm,` |
| `ca` | `eh...`, `mm...`, `doncs...`, `a veure,`, `mm,`, `eh,` |

The language is the one the reply is pinned to: `reply_language` when it is a tag, otherwise `language`. With neither set, or with `reply_language: "follow"`, only a list or the `"*"` entry is used. A reply language with no sounds is spoken clean, and `tts_hesitation_unavailable` is logged once per language at INFO.

What it costs and what it leaves alone:

- **First audio is not delayed.** The sound is the first audio. The reply's first word comes later by the length of the sound: 0.33 to 0.93 s (median 0.58 s) for the built-in sounds on ElevenLabs `eleven_v4_turbo`, before `tts_tempo`.
- **An interrupted reply keeps the words the caller heard, without the sound.** The sound's audio is taken out before played bytes are mapped to text. On that voice a sound takes about twice the audio of as many characters of the sentence behind it (0.8 to 3.5 times over 32 syntheses, median 2.0), so its share is counted double. A cut within that share keeps none of the reply.
- **A speculative reply that is dropped does not count.** Nobody heard it, so the reply that is spoken can still hesitate.
- **A reply the caller cuts before its audio starts does count.** The sound was already added to the text for the voice, so `TurnMetrics.hesitations` includes it and the next opening is said clean.

Each sound logs `tts_hesitation` at INFO with the `opener` and the start of the reply, and `TurnMetrics.hesitations` counts them for the turn. An opening that got none logs `tts_hesitation_skipped` at DEBUG with the reason: `already`, `not_a_word`, `short_opening`, `after_hesitation` or `draw`. `voice_session_config` logs `hesitation_rate`.

## Operator defaults

The server reads `TIMBAL_STT_PROVIDER`, `TIMBAL_STT_MODEL`, `TIMBAL_TTS_MODEL`, `ELEVENLABS_VOICE_ID` (before `TIMBAL_VOICE_ID`), `TIMBAL_VOICE_LANGUAGE`, and `TIMBAL_VOICE_GREETING`. `TIMBAL_VOICE_ID` alone also sets the default ElevenLabs voice. Use `voice_config.tts_provider` to select the output provider; there is no `TIMBAL_TTS_PROVIDER` reader in the server. An unknown STT or TTS provider id falls back to ElevenLabs for that session rather than refusing to boot.

`TIMBAL_VOICE_FILLER=1` enables default fillers. The `TIMBAL_VOICE_FILLER_MODEL`, `TIMBAL_VOICE_FILLER_SYSTEM_PROMPT`, `TIMBAL_VOICE_FILLER_DELAY_SECS`, `TIMBAL_VOICE_FILLER_REPEAT_SECS`, and `TIMBAL_VOICE_FILLER_THINK_DELAY_SECS` variables customize them. `TIMBAL_VOICE_FILLER_SOFT_TIMEOUT_SECS` and `TIMBAL_VOICE_FILLER_MESSAGE` add a spoken progress line during a quiet tool wait; see [Spoken fillers](/voice/fillers). See [Recording calls](/voice/recording) and [Background audio](/voice/background-audio) for their operator settings and transport limits.
