---
title: "Spoken Fillers"
description: "Have the assistant acknowledge a slow tool call with a short spoken phrase"
---

A filler is a short phrase such as "One moment, let me check." It can cover a tool's waiting period before the substantive answer arrives. It uses the session's speech output, so it can be heard on phone and browser transports.

## Enable one filler

Keep the agent and slow lookup from [Using tools](/voice/tools). This snippet includes a minimal agent so the page stands alone; later snippets on this page continue the same `agent`:

```python
from timbal import Agent

agent = Agent(
    name="voice_assistant",
    model="openai/gpt-6.1-terra",
    system_prompt="You help callers check deliveries. Reply in one or two short spoken sentences.",
    voice_config={"language": "en", "greeting": "Hi, I can help check your delivery."},
)
agent.voice_config["filler"] = {"enabled": True}
```

Restart the server and start a new session. Ask "Check order 101." When the lookup remains pending, the assistant can say a short waiting phrase, then give the delivery result. Turn the browser thinking sound off for this test so you can hear the filler behavior on its own.

The default delay is one second; generation has a five-second timeout. A fast tool gets no filler. If generation is too slow or the reply starts first, the phrase is skipped. `max_per_turn` defaults to 3. With `repeat_secs` unset you usually hear one filler for the tool, but a think-delay filler and a later tool call can each speak (`max_per_turn: 1` keeps only the first).

## Control the wording and timing

Replace that line with:

```python
agent.voice_config["filler"] = {
    "enabled": True,
    "delay_secs": 1.0,
    "timeout_secs": 5.0,
    "system_prompt": (
        "Write one brief, natural waiting phrase. "
        "Do not answer the question or claim the lookup succeeded. "
        "Return only the phrase, without quotes."
    ),
}
```

The session appends the [reply-language policy](/voice/configuration#reply-language) after this prompt. Generation starts when the tool call is detected and overlaps the delay. The phrase is spoken only while the turn still needs a filler and no substantive reply has started. Omit `model` to use the session's LLM, or set a full `provider/model` ID to choose a separate generator.

## Always say it, then pause

A quick lookup answered at once can sound less like someone checking than like a recording. To have the assistant say the phrase on every tool call and leave a moment before the result:

```python
agent.voice_config["filler"] = {
    "delay_secs": 0,
    "tools": ["get_delivery_status"],
    "phrases": {"en": ["One moment.", "Let me see."]},
}
agent.voice_config["tool_beat_secs"] = 0.5
```

`delay_secs: 0` speaks the phrase when the tool is called instead of after a second of waiting; ready-made `phrases` cost no model call. [`tool_beat_secs`](/voice/tools#speak-before-a-tool-call) is the minimum silence after the phrase has played and before the result is synthesized. The tool runs through both, so a lookup slower than the phrase plus the pause is not held back. Both are off by default.

`tools` names the calls that get the phrase, as the model calls them. Leave it out and every tool call does, which at `delay_secs: 0` includes a tool that says its own line: a transfer, a save, a hangup tool under a name of your own ("One moment." before "Goodbye."). A turn that calls a tool outside the list says no filler from that call on. `end_call` and the other built-in hangup names never get one.

If the model says something itself before the call ("Sure."), the filler stays quiet, and the same pause follows the model's words.

## Longer waits

For tools that legitimately take longer, opt into repeats:

```python
agent.voice_config["filler"] = {
    "enabled": True,
    "delay_secs": 1.0,
    "repeat_secs": 6.0,
    "max_per_turn": 2,
}
```

## Progress line during a long tool

A client can show a status such as "Calling lookup…" while a tool runs. That event is not speech, so a caller on the phone still hears silence. `soft_timeout_secs` speaks a short line once the caller has heard no agent audio for that many seconds during a tool wait, then keeps waiting for the result.

With `soft_timeout_secs` unset, a tool wait is unchanged. When `soft_timeout_secs` is set, the classic `delay_secs` tool-wait path is not used; `think_delay_secs` still covers silence before the first tool. A tool that finishes inside the window stays silent. The window counts only while a tool is running: the model writing its answer after the tool returns is not a tool wait. Audio already playing resets the wait, so the line does not talk over a preamble or the answer. The caller can interrupt the line the same way they interrupt a reply. A hangup tool does not get the line: `end_call`, `hangup`, and any tool that has entered `session.commit_hangup()` stay silent, so a progress phrase cannot sit in front of the goodbye.

```python
agent.voice_config["filler"] = {
    "enabled": True,
    "soft_timeout_secs": 1.5,
    "message": "One moment, I'm checking that.",
}
```

`message` is spoken directly, with no extra model call. Omit it to use `phrases` when one matches the call's language, or the filler generator otherwise. `repeat_secs` speaks another line after that much further silence, up to `max_per_turn`. ElevenLabs uses `-1` to disable this timeout; omit `soft_timeout_secs`, or set it to `-1`, for the same result.

## Before the first tool call

A reasoning model can think for several seconds before it says or calls anything, and a tool-call filler cannot cover that. `think_delay_secs` arms the filler when the turn starts: if nothing has been said and no tool has been called that long after the user finished, the first filler is spoken anyway. A tool call before then still gets its filler after `delay_secs`, whichever comes first. A tool called after that filler gets one of its own, `delay_secs` after the later of the call and the filler, even without `repeat_secs`; `max_per_turn: 1` turns that off.

Pair it with `phrases`, ready-made lines for the first filler of a turn. They are spoken with no LLM round trip, so the line lands on time; follow-ups are still generated from the request, so they can say what the assistant is working on. Within a call, every line is heard once before any repeats, and a line does not come back until at least half the others have been said. Key them by the call's language, with `"*"` for any other:

```python
agent.voice_config["filler"] = {
    "enabled": True,
    "model": "google/gemini-3.5-flash",
    "think_delay_secs": 1.5,
    "phrases": {
        "en": ["Mm, let me see.", "One second.", "Let me check."],
        "es": ["Mmm, déjame ver.", "Un segundo.", "Vale, lo miro."],
    },
    "repeat_secs": 6.0,
    "max_per_turn": 4,
}
```

The line said on the previous turn is avoided when there is another to choose. A language with no entry falls back to a generated first line. Regions are dropped on both sides, so an `"es-ES"` key serves a call configured as `"es"` and the other way round.

The language is the one the reply is pinned to: `reply_language`, else `language`. When neither pins it (`reply_language="follow"`, or both unset), it is the language the caller is speaking, and `language` until one is known.

A generated filler uses the same reply-language policy as the conversation. A pinned language pins the phrase. Otherwise the phrase is asked for in the language the caller is speaking, and follows the user's latest substantive message until one is known. See [Reply language](/voice/configuration#reply-language).

### Callers in more than one language

`session.spoken_language` is the language the caller is speaking. It comes from one of two places:

- **The transcriber**, when it names the language of each utterance: Deepgram Nova-3 with `language: "multi"`, Deepgram Flux multilingual, and ElevenLabs Scribe with `stt_extra: {"include_language_detection": True}`. An utterance needs four words to count, and a shorter one keeps the language the call had: on one or two words the transcribers get it wrong (measured: Telugu for "Okey.", Turkish for "Sí."). With `stt_languages` set, a language outside the list is ignored.
- **Your application**, with `session.set_spoken_language("es")`. Use it when the transcriber is set to one language (it then reports none) or when you tell the language better from what the caller says. It wins over the transcriber and stays until you set it again; `None` hands it back.

```python
from timbal.voice import current_voice_session


def note_language(text: str) -> None:
    """Call it with the turn: from the system prompt callable, or a tool."""
    session = current_voice_session()
    if session is not None:
        session.set_spoken_language(my_detector(text))  # "es" | "ca"
```

Neither moves the transcriber's hint or the reply instruction: with `reply_language="follow"` the model still answers in the language of the caller's latest message. The ready-made line is chosen when it is due, not when the turn starts, so a language set during the turn is the one spoken.

Only the session agent's own reply is spoken. An agent it calls as a tool streams its text through the same run, and that text — working notes, a document being drafted — is never read aloud.

Repeats are bounded and stop being useful once the answer arrives or the turn is interrupted. Test with representative tool latency; repeated acknowledgements can distract from the actual answer. Fillers consume LLM and TTS usage and appear in transcripts as fillers. First-audio latency can measure a filler instead of the useful answer; see [Events and usage](/voice/observability).

Set `agent.voice_config["filler"] = {"enabled": False}` to explicitly disable an inherited filler. Empty objects mean unset, rather than disabling a server default.
