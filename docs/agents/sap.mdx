Import SAP tools from `timbal.tools`. Each instance represents one SAP operation, view, agent or script that your application configures: its endpoint, columns, input model and manifest. The caller supplies only business inputs.

## Connect SAP

Store SAP credentials on the Timbal platform as a connection, and bind a tool to it with `integration="<connection id>"`.

- **`sap`** holds the system's `host` and `port` (443 by default), an optional three-digit `sap_client`, and an OAuth client: `token_url`, `client_id` and `client_secret`. The HTTP tools run the OAuth 2.0 client-credentials grant against `token_url` themselves. They send the client ID and secret with HTTP Basic authentication, accept only a bearer token, and never follow a redirect. The token is cached in the worker until about two minutes before it expires, and a token SAP rejects is dropped. Neither the secret nor a token appears in errors, logs or traces.
- **HANA Cloud.** A `sap_hana` connection supplies `host`, `user` and `password`. Without one, pass `host`, `user` and `password` to the tool, or set `SAP_HANA_USER` and `SAP_HANA_PASSWORD`. With a connection bound, those settings aren't used.

<Note>
The platform hands an org's shared connections only to org admins. A run can use a bound SAP connection only when an org admin triggers it.
</Note>

## Decide what agents may do

Gate SAP tools with the controls every Timbal tool has:

- **Read-only runs.** Every SAP tool declares [`read_only`](/agents/tools#read-only-tools). Reads such as `SAPHANARead`, `SAPHANAQuery`, `SAPODataRead`, `SAPCDSRead` and `SAPAgentGetTask` are read-only, and so are MCP tools bound with `read_only=True`. Writes and GUI scripts are not. `SAPSOAPOperation` and `SAPBAPI` take `read_only` from your configuration, and a read-only one can't declare document types, customizing or a commit. A run with [`tool_policy="read_only"`](/deployment/self-hosted#request-context) offers its agents only the readers.
- **Approvals.** Mark writes with [`requires_approval`](/human-in-the-loop/approval-gates) so a person confirms each one, or the ones a callable selects, before it reaches SAP.
- **Offer only what you mean.** Give an agent the SAP tools its task needs and nothing else.

GUI scripts are the exception: `SAPGUIScript` runs only in deterministic workflows, and refuses when an agent selects it.

Every call records on its span, under `metadata.sap`:

- `selected_by`: `agent` when a Timbal agent called the tool, directly or through a workflow it invoked, otherwise `workflow`;
- `agent`: the selecting agent's path;
- `route`: the kind of operation, such as `hana_view`, `published_api` or `cds_view`;
- `object`: the SAP object;
- `document_types`: for writes, the SAP document types the operation can create;
- `customizing`: the system, client and transport request of a customizing change.

Set `agent_selected=True` on `SAPAccess` when a model outside Timbal selects operations before they reach Timbal.

## Read a HANA Cloud view

Install SAP's `hdbcli` Python package in the worker that connects to HANA Cloud. Grant the database user read access to the approved views only. This example reads one page of a fictional reporting view in a deterministic workflow.

```python
from timbal import Workflow
from timbal.tools import SAPAccess, SAPHANARead

access = SAPAccess(consumer="order-report")
orders = SAPHANARead(
    name="read_open_orders",
    access=access,
    integration="hana-reporting-connection",
    schema_name="REPORTING",
    view="OPEN_ORDERS",
    columns=("ORDER_ID", "STATUS"),
    order_by=("ORDER_ID",),
)
report = Workflow(name="order_report")
report.step(orders, filters={"STATUS": "OPEN"}, limit=100)
```

A `host` set on the tool must match the connection's. The tool quotes configured identifiers and binds filter values. Choose an ordering that uniquely identifies each row, and pass `next_offset` from the result to request another page. The connection uses port 443, certificate validation and a read-only transaction. HANA sees the selecting agent's path, or the tool's name, as the session's application. [SAP HANA client reference](https://help.sap.com/doc/b01bb8ddc72e41f795034092b9bf541d/2.30/en-US/SAP_HANA_Client_Interface_Programming_Reference_en.pdf)

`SAPHANAQuery` accepts a single SELECT or WITH statement plus bindings, which a model may write. Its database identity must have read access only to the authorized objects, including access inherited through roles. `SAPHANAWrite` binds values to a single DML statement configured in the application. Give it a separate, restricted write identity. Source replication into HANA Cloud belongs to the customer's SAP data pipeline.

## Published APIs and CDS

- **OData.** Use `SAPODataRead` with a fixed entity-set URL, selected properties and a stable order. It supports V2 and V4 collection responses, equality filters, and one page per call. Mark released or customer-developed analytical CDS services with `cds=True`. Use `SAPODataWrite` with a fixed operation URL and method, a Pydantic input model and, where required, the service's `csrf_endpoint`. For updates and deletes on an entity set, declare the OData key names in `key_fields`. The tool encodes the validated key values into the resource URL and sends the remaining fields as the payload. The token fetch and write share the same cookie session. [SAP OData token handling](https://help.sap.com/docs/SAPUI5/b2f662dd9d7a4ec680056733050b4d34/9613f1f2d88747cab21896f7216afdac.html)
- **SOAP.** Configure `SAPSOAPOperation` from the published WSDL. Supply `version`, `action`, `operation_tag` in ElementTree expanded-name form, and `build_element(payload)` to map a validated model to that operation's XML. The binding creates the envelope and detects SOAP faults.
- **BAPIs.** Use the SOAP binding when the BAPI is published as a web service. For a published native RFC binding, `SAPBAPI` accepts a fixed function name, a typed input model and a per-call `connect()` factory. It expects an authenticated, stateful RFC SDK connection exposing `call()` and `close()`. Configure the destination, protected channel, driver timeout and customer identity in that factory. Set `commit=True` only for BAPIs that require an explicit transaction commit. The tool checks BAPI return messages before committing.
- **ABAP SQL service.** `SAPCDSRead` runs a parameterized query against a released CDS view. Supply a fresh DB-API connection from SAP's ODBC driver for ABAP, for example through `pyodbc.connect` with an authenticated TLS-enabled DSN. Restrict the service binding to the published views. [SAP SQL service](https://help.sap.com/docs/abap-cloud/abap-integration-connectivity/inbound-data-integration-using-sql)

With a connection bound, the HTTP tools refuse an `endpoint` or `csrf_endpoint` that is not on the connection's host and port, whatever the token's source. They add the connection's `sap-client` when the URL has none. An async `token_provider()` supplied by the application replaces the connection's OAuth client.

Set `document_types` explicitly on each operation capable of writing. An empty tuple declares that the operation can't create an SAP application document.

```python
from pydantic import BaseModel, ConfigDict, Field
from timbal.tools import SAPAccess, SAPODataWrite

class OrderInput(BaseModel):
    model_config = ConfigDict(extra="forbid")
    SalesOrderType: str = Field(max_length=4)
    SoldToParty: str = Field(max_length=10)

create_order = SAPODataWrite(
    name="create_sales_order",
    access=SAPAccess(),
    integration="customer-sap-connection",
    object_name="A_SalesOrder",
    endpoint="https://tenant.example/sap/opu/odata/sap/API_SALES_ORDER_SRV/A_SalesOrder",
    csrf_endpoint="https://tenant.example/sap/opu/odata/sap/API_SALES_ORDER_SRV/",
    method="POST",
    document_types=("sales_order",),
    input_model=OrderInput,
    requires_approval=True,
)
```

The connection's host is `tenant.example`. Adapt the payload model to the required fields of the customer's service.

## MCP servers and SAP-managed agents

`SAPMCPServer` uses Timbal's MCP client. Configure `kind="hana-ai"` for SAP's local HANA toolkit, or `kind="gateway"` for a customer-enabled SAP-managed MCP endpoint. Bind each permitted remote name in `manifest` to a `SAPMCPBinding(read_only=..., document_types=...)`. Tools outside the manifest are not offered. The local HANA toolkit needs read-only tools and a read-only HANA identity. Pin the deployed toolkit version and review tool definitions when it changes. [SAP HANA AI Toolkit architecture](https://architecture.learning.sap.com/docs/ref-arch/2ecb7e)

For a third-party HTTPS MCP server, select `third-party-hana` for bounded HANA reads, `third-party-api` for published application APIs, or `third-party-cds` for scoped CDS reads. Each tool in the manifest needs an `input_model` owned by the application. Timbal exposes that schema to the agent and validates the arguments locally. Apply the underlying SAP quotas at the server as well, especially if one tool call issues several SAP requests. [SAP third-party MCP architecture](https://architecture.learning.sap.com/docs/ref-arch/137800)

Use stdio for a locally installed HANA toolkit, or authenticated HTTPS for a remote server. Give each authenticated principal its own server instance. Supply SAP-scoped credentials through the transport configuration, and close the server when its session ends.

`SAPAgentSend` and `SAPAgentGetTask` implement inbound A2A 0.3 HTTP+JSON. Bind the exact send URL and task collection URL from the tenant's agent interface. Configure capability or scenario metadata from the agent interface using `request_metadata`. For asynchronous runs, supply an HTTPS `callback_url` owned by the application and an optional `callback_token`. Use the returned task ID to read state where the gateway exposes GetTask. Provide an async token provider that obtains a gateway-audience token for the current authenticated user. `SAPTokenExchange` performs the SAP Cloud Identity Services OAuth token exchange for tenants configured for that flow. Registration, trust, application dependencies and named-user authorizations are configured in SAP. [SAP inbound A2A architecture](https://architecture.learning.sap.com/docs/ref-arch/fe0d1d) · [A2A HTTP binding](https://a2a-protocol.org/v0.3.0/specification/) · [SAP token exchange](https://help.sap.com/docs/cloud-identity-services/cloud-identity-services/configure-client-to-call-identity-authentication-token-exchange)

## Deterministic GUI scripts and customizing

`SAPGUIScript` runs on a Windows worker with SAP GUI Scripting and `pywin32`. Register the designated non-production system ID, three-digit client, technical user, typed input model and installed `script(session, payload, transport_request)` function. The function and input model must be importable in a spawned Windows process. The worker selects exactly one matching authenticated session. It rejects concurrent scripts and stops the script process on timeout. Actions already accepted by SAP may have taken effect.

A customizing proposal can be produced as an ordinary workflow artifact for customer review. To execute one, bind the published operation or GUI script to the designated non-production system, and supply `SAPCustomizing` with that system, its client and the transport request.

- **GUI scripts** receive the transport number.
- **HTTP operations** use the designated HTTPS origin as `nonproduction_system`. The tool checks the endpoint against it and sets the SAP client. Set `transport_query_parameter` when the service accepts the transport in a query parameter, or bind it in the documented operation payload.
- **Native BAPIs** check the destination's system ID and client, and set the configured `transport_parameter`.

The call's span records the transport request. The customer owns transport release, testing and production import.

## Limits and logs

Share one `SAPAccess` instance among the tools that use the same SAP system and quota in a worker. The defaults are 1,000 rows per SQL or OData page, 5,000,000 bytes per result, 60 calls per minute, four concurrent calls and a 60-second deadline. You can change each of them, and per-consumer limits apply to each agent or `consumer`. Failed upstream calls can open a circuit for a cooldown period (`failure_threshold`, `cooldown_seconds`). When several processes share an SAP quota, divide it across them or apply it at a gateway. Native drivers need their own connection and operation timeouts. A timeout after a write has been sent can leave its outcome unknown. Reconcile it in SAP before retrying.

SAP tools don't print their inputs or results to the worker's event logs. The `timbal.sap` logger emits one line per call with the route, who selected it, the operation, the SAP object, the outcome, volume and latency. Set retention for traces, agent messages and tool results to suit the customer's data.
